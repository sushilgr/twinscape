# Setup

This takes about ten minutes. The open-data samples need no accounts or keys. Google Photorealistic 3D Tiles need a Google Maps Platform key; see [Google API key](#3-google-api-key-optional) below.

## Requirements

| | Tested with | Notes |
|---|---|---|
| Houdini | 22.0.368 (Indie), macOS on Apple silicon | Houdini FX, Core or Indie. Apprentice can't use Houdini Engine. |
| Unreal Engine | 5.8, macOS | Nanite, Lumen and virtual textures are used throughout. |
| Houdini Engine for Unreal | the plugin version matching your Houdini 22 build | Needed for the Unreal side only. |
| Python packages | all bundled with Houdini 22 (`numpy`, `Pillow`, `requests`, `OpenImageIO`, `pxr`) | `DracoPy` is installed automatically into your Houdini user site the first time you fetch Google 3D Tiles. |

Windows and Linux use the same code paths (no compiled parts, standard Houdini and Unreal APIs) but haven't been tested yet. The screen-recording helpers in `earthtwin/demo_*.py` are macOS-only and optional.

## 1. Get the code

```bash
git clone https://github.com/sushilgr/twinscape.git
```

You can clone it anywhere. Nothing depends on the folder name.

## 2. Install into Houdini

```bash
cd twinscape
python3 install.py
```

`install.py` writes a [Houdini package](https://www.sidefx.com/docs/houdini/ref/plugins.html) named `twinscape.json` into your Houdini user preferences folder. The package:

* sets `$TWINSCAPE` to the repository,
* adds `houdini/python` to `PYTHONPATH` (the `earthtwin` package), and
* adds `houdini/` to `HOUDINI_PATH`, so the HDA in `houdini/otls/` loads.

Houdini Engine inside Unreal reads the same preferences, so this one step covers both apps.

Options:

```bash
python3 install.py --houdini 22.0          # pick a version when several are installed
python3 install.py --prefs "<prefs dir>"   # an explicit prefs folder
python3 install.py --uninstall
```

If you prefer to do it by hand, copy this into `<Houdini prefs>/packages/twinscape.json` and set the path:

```json
{
  "env": [
    {"TWINSCAPE": "/path/to/twinscape"},
    {"PYTHONPATH": {"value": "$TWINSCAPE/houdini/python", "method": "prepend"}}
  ],
  "path": "$TWINSCAPE/houdini"
}
```

Houdini prefs folders: macOS `~/Library/Preferences/houdini/22.0`, Windows `Documents/houdini22.0`, Linux `~/houdini22.0`.

**Check it:** restart Houdini, then

* open `houdini/scenes/Twinscape_demo.hip`. Midtown should cook straight away from the bundled sample.
* or from a terminal: `hython tools/selftest.py`, which should print `PASS`.

**About the HDA licence:** the bundled HDA was saved with Houdini Indie, so Houdini FX treats it as a limited-commercial asset. To get a copy saved under your own licence, rebuild it from source. The whole network is generated by code:

```bash
hython tools/build_hda.py
```

## 3. Google API key (optional)

Only needed for **Google Photorealistic 3D Tiles**, the Google satellite imagery source and the Google Elevation API.

1. In the [Google Cloud console](https://console.cloud.google.com/), create or pick a project with billing enabled.
2. Enable the **Map Tiles API**. Enable the **Elevation API** too if you want Google terrain heights.
3. Create an API key. It's a good idea to restrict it to those APIs.
4. Give Twinscape the key in one of these ways:
   * paste it into the **API key** field in the panel and tick **Remember** (saved to `~/.twinscape/google_api_key`, readable only by you), or
   * set the environment variable `GOOGLE_MAPS_API_KEY`, or
   * type it into the HDA's **Google API Key** parameter. This is stored in the .hip, so avoid it for scenes you share.

The key is read when fetching and never written into caches, manifests or logs. Before you use Google content, read [Data & licensing](DATA_AND_LICENSING.md).

## 4. Unreal project

The repository includes a lightweight UE 5.8 project, `unreal/TwinscapeUE`: just a project file, renderer config and a start-up script. Everything else (materials, levels, meshes) is generated the first time you build an area.

1. **Install Houdini Engine for Unreal** into the project. Use the plugin build that matches your Houdini version, from your Houdini installation or the [SideFX GitHub releases](https://github.com/sideeffects/HoudiniEngineForUnreal/releases). Copy the plugin folder to:
   ```
   unreal/TwinscapeUE/Plugins/HoudiniEngine/
   ```
   (Installing it as an engine plugin works too.)
2. **Open** `unreal/TwinscapeUE/TwinscapeUE.uproject` and let shaders compile the first time.
   If the Output Log says `Failed locating or loading libHAPIL`, the plugin was built for a different Houdini build than the one it found. Point it at yours in *Project Settings > Plugins > Houdini Engine > Use Custom Houdini Location* and restart the editor. On macOS the folder is
   `/Applications/Houdini/Houdini<version>/Frameworks/Houdini.framework/Versions/Current/Libraries`; on Windows, `C:\Program Files\Side Effects Software\Houdini <version>\bin`.
3. A **Twinscape** menu appears in the main menu bar. If it doesn't, check the Output Log for `[Twinscape]` messages.
4. **Twinscape > Build sample: Midtown** builds a playable level from the bundled open-data sample in a few minutes.
5. **Optional, to play as the UE5 mannequin:** *Add > Add Feature or Content Pack > Third Person*, then rebuild the sample. Twinscape picks up `BP_ThirdPersonCharacter` automatically.

The start-up script (`Content/Python/init_unreal.py`) finds the repository from the project's location, so keep the project inside the clone. If you move it elsewhere, set the `TWINSCAPE` environment variable to the repository path before starting Unreal.

Use an existing project instead by adding `unreal/scripts` to the Python path and calling the same functions; see [UNREAL.md](UNREAL.md#using-your-own-project).

## Troubleshooting

| Symptom | Fix |
|---|---|
| *Twinscape City Builder* isn't in the Tab menu | The package isn't loaded. Re-run `install.py`, restart Houdini, and check *Windows > Python Shell*: `import os; os.environ.get("TWINSCAPE")`. |
| Node warning "Area not fetched yet" | The settings don't match a cached area and **Auto Fetch On Cook** is off. Press **Fetch** or open the panel. |
| Fetch fails with a 403 | The key is missing the Map Tiles API, or billing isn't enabled on the project. |
| "DracoPy is required" | No network access to PyPI from Houdini. Install it into Houdini's Python with `hython -m pip install --user DracoPy`. |
| Unreal: "Failed to start the Houdini Engine Session" / "Failed locating libHAPIL" | Set *Use Custom Houdini Location* (see step 4.2) and restart Unreal. |
| Unreal hangs on "cooking … in Houdini Engine" after a crash | A stale named pipe from the previous session. Quit Unreal, delete `/tmp/hapi` (macOS/Linux), reopen. |
| Unreal: "HDA import failed" | Houdini Engine couldn't start a session. Check *Houdini Engine > Session* and that Houdini 22 is installed. |
| Unreal: meshes look faceted or shard in the editor | The Nanite fallback isn't at full detail yet. Run *Twinscape > Optimize baked meshes*. |
| Unreal on macOS crashes while screen recording | A known macOS window-server issue with long blocking operations. Twinscape's heavy steps run per tick to avoid it; record with the Movie Render Queue instead (see UNREAL.md). |
| Two definitions of the HDA | An older `earthtwin.json` package is also installed. Remove it from `<prefs>/packages`. |
