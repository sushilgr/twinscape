## Google content: keep it local

Google's Map Tiles terms restrict pre-fetching, caching, offline use and building derived geometry from their tiles, and they require visible attribution. Twinscape's Google mode stores the decoded mesh and texture atlas so Houdini and Unreal can use them. Treat that as **internal look-dev within your own Google agreement**:

* never commit or upload Google-derived caches (`g3d.bgeo.sc`, `g3d_atlas_*.jpg`), baked Unreal meshes or USD exports. `.gitignore` excludes the cache for this reason;
* show "Map data ©Google" wherever the imagery appears;
* use **Delete Google Data** in the panel (or on the HDA) when you're done.

For anything you ship or hand to a client, build from open data, or from data you've licensed for that use.

## What's in this repository

* **`cache/midtown_d12e301dc4`, `cache/lower_manhattan_e2f8b1722e`:** open data only. USGS 3DEP elevation and NAIP imagery (public domain), buildings derived from OpenStreetMap (© OpenStreetMap contributors, ODbL 1.0; this derived data is shared under the same licence), heights from NYC Open Data.
* **`cache/_shared`:** procedural facade textures generated by Twinscape (MIT).
* **`unreal/scripts/T_ET_StreetDetail.png`:** a procedural asphalt detail texture generated by Twinscape (MIT).
* **`docs/media`:** screenshots and video rendered by the author from Twinscape scenes, some containing Google Photorealistic 3D Tiles imagery with the "Map data ©Google" credit visible. They're there to document the project, not as data to reuse.

No Google-derived geometry or textures are included.

## API keys

Keys are read from the panel, `GOOGLE_MAPS_API_KEY` or `~/.twinscape/google_api_key` (the panel writes that file with owner-only permissions). They're never written into caches, manifests, scenes or logs, unless you type a key into the HDA's own *Google API Key* parameter, which is saved with the .hip like any parameter.
